TASK 3 · MULTI TOUCH

图片查看器

爱达·魔都号 —— 双指捏合缩放、双击放大、放大后拖动查看细节。

100%
双指缩放 / 旋转请用手机打开（电脑可用滚轮 / 双击）

操作方式

双指捏合 → 缩放 1~4 倍；双指旋转 → 任意角度转动（旋转时可能轻微越界，松手自动拉回）；双击 → 1x / 2x 切换；放大后单指拖动 → 查看细节。

如何保证"缩放不跳"（答辩用）

  1. 先算两指中点，再把中点换算成图片坐标：u = (中点 - 平移量) / 当前总缩放，这个点就是手指按住的画面内容。
  2. 缩放后重新反推平移量：t = 中点 - u × 新总缩放。中点下面的那块画面始终不动，所以不会跳。
  3. 所有缩放都以 transform-origin: 0 0 为基准，数学上只有一个平移量需要修正，不会出现原点半途变化。
  4. 捏合过程中超出边界用阻尼（0.3 倍系数）软化，松手后统一硬夹紧并补 0.25s 过渡，所以边缘手感是"顶一下再弹回"。
  5. 横竖屏切换只重算容器尺寸与适配比例，保留当前 scale、角度和平移量再夹紧，状态不丢。
  6. 双指旋转同一套思路：θ = θ₀ + (atan2 差值)，再按 t = 中点 - s × R(θ) × u 反推平移，旋转中心同样钉在两指中点。

accelerationIncludingGravity 与 acceleration 的区别

acceleration 是设备自身运动产生的加速度，静止放在桌上时约为 0； accelerationIncludingGravity 则把重力也算进去，静止时约 9.8 m/s²（朝下的那根轴）。 摇一摇要判断"有没有被晃动"，用后者更稳：静止基线是 9.8，合成值超过 18 就说明明显在晃； 而 acceleration 在部分机型上不提供或恒为 0，容易误判，所以本页取 accelerationIncludingGravity。

为什么必须做降级

  1. 桌面浏览器和部分安卓设备没有加速度传感器，devicemotion 要么不触发、要么数值全为 0，页面会一直"抽不出来"，看起来像坏了。
  2. iOS 13+ 要求用户点击后才能申请运动权限，直接监听永远拿不到数据。
  3. 手机可能在浏览器设置里关闭了"运动与方向"权限，同样收不到事件。
  4. 所以本页做了两层兜底：1.5 秒内没收到有效数据就提示"当前设备不支持，请用手机打开"，并保留「点我抽一次」手动按钮，保证任何设备都能完成一次抽取。

踩过的坑与解决办法

坑：一开始只用"是否收到过 devicemotion 事件"判断设备是否支持，结果桌面 Chrome 也会触发事件， 但三根轴的值全是 0，页面既不提示不支持、也永远摇不出结果，看起来像坏了。
办法：加了有效性过滤——合成加速度大于 0.5 才算"收到了真实数据"， 并且 1.5 秒内没有有效数据就判定不支持、显示降级提示；同时按钮始终可用，任何设备都能完成抽取。

实现要点

  • 合成加速度：√(x² + y² + z²)，静止约 9.8，超过 18 判定为摇动。
  • 冷却：记录上次触发时间，1.5 秒内的后续事件直接忽略，保证"一次摇动只抽一次"。
  • 事件节流：用 requestAnimationFrame 控制加速度条刷新，避免高频重绘。

倾斜手机试试

alpha / beta / gamma 分别是什么

alpha 是绕垂直轴的旋转（0~360°，像转盘旋转，指南针方向）； beta 是绕左右轴的旋转（-180~180°，手机前后俯仰，屏幕朝自己时约 0°）； gamma 是绕前后轴的旋转（-90~90°，手机左右侧倾）。 本页用 beta 控制纵向位移、gamma 控制横向位移，alpha 不参与。

为什么要做基线校准

手机拿在手里本来就不是水平的，直接拿 beta/gamma 当位移会让画面一打开就偏到一边。 所以代码在收到第一帧时把当时的 beta/gamma 记成"零点"，之后只用相对变化量， 拿手机的姿势再随意，画面也能保持居中。

为什么不会抖

  • 传感器事件频率很高（每秒几十次），如果直接写 transform，画面会跟着传感器噪声抖。
  • 所以只把角度换算成目标位移，再用 requestAnimationFrame 每帧向目标 lerp（系数 0.12），运动自然顺滑。
  • 位移还做了 ±46px 上限，倾斜再狠也不会把景物拖出舞台。

无传感器时怎么办

电脑或没有陀螺仪的设备收不到 deviceorientation，页面会在 1.5 秒后自动切换成 鼠标模拟：鼠标在页面上移动即可看到同样的视差，不会白屏也不会报错。
